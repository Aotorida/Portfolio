Stagiaire analyste applicatif

Groupe industriel · cycle du combustible nucléaire

Le contexte

Le système d'information d'Orano compte un grand nombre d'applications qui s'échangent des données. Le problème : personne n'avait de vue d'ensemble claire de ces échanges, ce qui rend chaque évolution plus risquée qu'elle ne devrait l'être.

Mes missions

  • Analyse technique des applications et de leurs flux pour construire une cartographie applicative.
  • Mise en évidence des interactions entre systèmes, pour aider à repérer les dépendances et optimiser l'architecture du SI.
  • Structuration des données applicatives dans Jira Assets.
  • Rédaction et mise à jour de la documentation technique et fonctionnelle sur Confluence et ARIS, pour garder une trace de chaque évolution.

Ce que j'en retiens

J'ai appris à lire un SI dans son ensemble plutôt qu'application par application, et à écrire une documentation que d'autres peuvent vraiment utiliser.

Université Paris-Dauphine — PSL

Stagiaire développement d'outils internes

Exploitation du SI

Le contexte

Pour connaître l'état d'une machine virtuelle, l'équipe d'exploitation devait ouvrir plusieurs consoles : vCenter pour la VM, Veeam pour les sauvegardes, Centreon pour la supervision, Satellite pour les mises à jour. L'idée était de tout regrouper au même endroit.

Mes missions

  • Développement d'une interface web qui centralise et affiche les informations des VM issues de différents environnements.
  • Connexion aux outils d'exploitation (vCenter, Veeam, Centreon, Red Hat Satellite, Mercator) via leurs API pour récupérer et croiser les données.
  • Mise en place d'un portail d'accès aux différentes consoles d'exploitation.
  • Conteneurisation de l'application avec Docker et suivi du code avec Git.

Ce que j'en retiens

Mon premier vrai projet au service d'utilisateurs internes : comprendre leur besoin, composer avec des API toutes différentes, et livrer un outil utilisé au quotidien.
